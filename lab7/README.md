## Что делает приложение

Небольшой HTTP API на стандартной библиотеке Python (`http.server`), состояние заказов хранится в Redis. Один заказ — JSON-объект: `id`, `items`, `status`, `createdAt`, `updatedAt`, `history`.

Конечный автомат статусов:

```
created ──► cooking ──► delivering ──► done
   │           │
   └───────────┴──► cancelled
```

| Из \ В | `cooking` | `delivering` | `done` | `cancelled` |
|--------|-----------|--------------|--------|-------------|
| `created` | да | нет | нет | да |
| `cooking` | — | да | нет | да |
| `delivering` | нет | — | да | нет |
| `done` / `cancelled` | нет | нет | нет | нет |

Отменить заказ можно только до передачи курьеру; повторная установка того же статуса возвращает `200` без изменения истории.

### Эндпоинты

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET` | `/health` | проверка API и соединения с Redis |
| `POST` | `/orders` | создать заказ (`items` — непустой список) |
| `GET` | `/orders` | список заказов, фильтр `?status=` |
| `GET` | `/orders/{id}` | карточка заказа |
| `PATCH` | `/orders/{id}/status` | сменить статус (`{"status": "cooking"}`) |
| `POST` | `/orders/{id}/cancel` | отменить заказ |

Коды ошибок: `400` — битый JSON, `404` — заказ не найден, `409` — недопустимый переход или отмена, `422` — нет `items` / неизвестный статус.

## Запуск

Из корня `lab7`:

```bash
docker compose up --build
```

Что происходит:

1. собирается образ `api` из `python:3.12-slim`, ставятся зависимости;
2. поднимается `redis:7-alpine` с AOF-персистентностью и томом `redis-data`;
3. `api` стартует **после** того, как healthcheck Redis станет зелёным (`depends_on: condition: service_healthy`);
4. API слушает `8000` внутри контейнера, наружу проброшен порт из `API_PORT` (по умолчанию `8000`).

Остановить: `docker compose down`. Остановить и удалить данные Redis: `docker compose down -v`.

## Проверка работоспособности

### 1. Healthcheck

```bash
curl http://localhost:8000/health
# {"status": "ok", "redis": "ok"}
```

```bash
docker compose ps
# delivery-api    ... (healthy)
# delivery-redis  ... (healthy)
```

### 2. Создать заказ

```bash
curl -X POST http://localhost:8000/orders \
  -H "Content-Type: application/json" \
  -d '{"items": [{"name": "Пицца Маргарита", "qty": 1}, {"name": "Лимонад", "qty": 2}]}'
```

Ответ `201`:

```json
{
  "id": "3f9c1a2b",
  "items": [{"name": "Пицца Маргарита", "qty": 1}, {"name": "Лимонад", "qty": 2}],
  "status": "created",
  "createdAt": "2026-11-25T10:15:00+00:00",
  "updatedAt": "2026-11-25T10:15:00+00:00",
  "history": [{"status": "created", "at": "2026-11-25T10:15:00+00:00", "by": "customer"}]
}
```

### 3. Сменить статус

```bash
curl -X PATCH http://localhost:8000/orders/3f9c1a2b/status \
  -H "Content-Type: application/json" \
  -d '{"status": "cooking", "by": "restaurant"}'
```

Недопустимый переход (например, `created → done`) вернёт:

```json
{"error": "transition created -> done is not allowed"}
```

с кодом `409`.

### 4. Получить статус

```bash
curl http://localhost:8000/orders/3f9c1a2b
```

### 5. Отмена

```bash
curl -X POST http://localhost:8000/orders/3f9c1a2b/cancel
```

После статуса `delivering` отмена вернёт `409` — заказ уже у курьера.

### 6. Логи

```bash
docker compose logs -f api
docker compose logs --tail=50 redis
```

В логах API видны строки вида `172.18.0.1 "POST /orders HTTP/1.1" 201 -`.

## Переменные окружения

| Переменная | Где используется | Значение по умолчанию |
|------------|------------------|------------------------|
| `API_PORT` | проброс порта в `compose.yaml` | `8000` |
| `REDIS_URL` | подключение API к Redis | `redis://redis:6379/0` |
| `PORT` | порт внутри контейнера | `8000` |

Значения по умолчанию заданы прямо в `compose.yaml`; при необходимости их можно переопределить переменными окружения или файлом `.env` (в репозиторий не коммитится). Секретов в проекте нет.

## Как устроены сервисы

- **api** — `ThreadingHTTPServer`; на каждый запрос читает/пишет JSON в Redis-хэш `orders` (поле — id заказа). Healthcheck дергает `/health`, который делает `PING` в Redis.
- **redis** — хранит заказы, том `redis-data` сохраняет данные между перезапусками контейнеров; AOF включён.
- Общая сеть Compose создаётся автоматически (проект `food-delivery`); наружу открыт только порт API, Redis доступен лишь внутри сети.

## Ограничения учебной версии

- Нет авторизации и разделения ролей — поля `by` в истории носят справочный характер.
- Нет пагинации в `GET /orders` и ограничения размера `items`.
- Redis без пароля: это допустимо только внутри изолированной Compose-сети; для реального окружения нужен пароль и TLS.
