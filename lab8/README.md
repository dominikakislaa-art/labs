## Общие правила

Лабораторная работа выполняется по одной задаче из общего списка (номер задачи соответствует номеру в журнале) и состоит из трёх блоков:

1. **Пользовательская документация (Markdown)** — как пользоваться продуктом: доступ, основные сценарии, FAQ и типичные ошибки. Документ рассчитан на пользователя, которому не нужно читать исходный код.
2. **Техническая документация (Markdown)** — краткая архитектура, структура репозитория, запуск, ключевые модули и договорённости (конфигурация, переменные окружения).
3. **OpenAPI / Swagger** — спецификация небольшого API предметной области, не менее 4–6 операций (пути + методы). Реализация может быть заглушкой: mock-сервер, статическая спека со Swagger UI или минимальный код, отдающий OpenAPI. Главное — корректная и согласованная с текстами документация API.

Дополнительные условия:

- язык документации — **русский**; имена полей и путей API допускаются на английском;
- формат — Markdown в репозитории, OpenAPI — YAML или JSON (`openapi.yaml` / `openapi.json`);
- спецификация должна проходить базовую проверку структуры OpenAPI 3.x: валидные `info` и `paths`, хотя бы одна схема в `components` или inline;
- Swagger UI / Redoc / Stoplight подключаются по желанию; минимум — файл спеки и раздел в README о том, как её открыть;
- код реализации API может быть минимальным или stub, но документы должны быть полноценными и привязанными к предметной области, без общих шаблонов и шаблонных заглушек;
- ориентировочный объём пользовательской и технической документации — 3–6 экранов вместе, без копипаста определений без привязки к проекту;
- результат сдаётся ссылкой на **публичный** (или доступный без запроса доступа) репозиторий GitLab / GitHub.

## О проекте

«FoodTrack» — учебный сервис доставки еды, в котором клиент оформляет заказ и наблюдает за его движением от ресторана до двери. В рамках работы описаны три слоя продукта:

- **клиентский сценарий** — где увидеть текущий статус, что он значит, как посмотреть историю и отменить заказ;
- **инженерная часть** — конечный автомат статусов `created → cooking → delivering → done`, правила отмены, формат времени, коды ошибок, идемпотентность и пагинация;
- **контракт API** — 6 операций: создание заказа, карточка заказа, смена статуса, отмена, история статусов и список заказов с фильтром.

Пример сквозного сценария: заказ **№1042** (пицца «Маргарита», салат «Цезарь», морс) создан в 11:58, в 12:05 передан на кухню, в 12:24 — курьеру Дмитрию Соколову, в 12:41 доставлен. Все четыре события видны в истории статусов заказа.

### Как открыть спецификацию

Спецификация — обычный YAML-файл. Посмотреть её можно двумя способами:

1. **Swagger Editor** — открыть <https://editor.swagger.io> и импортировать `openapi.yaml` (File → Import File).
2. **Локальный сервер** — из корня `lab8` выполнить `python -m http.server 8000` и открыть <http://localhost:8000/openapi.yaml>; тот же адрес можно передать в Swagger Editor через File → Import URL.

Подробности и альтернативные способы проверки спеки — в [технической документации](tech.md).
