## Что делает модуль

Номер студенческого билета строится по правилу **`ГГ-ФФ-НННН-К`**:

| Часть | Значение | Ограничения |
|-------|----------|-------------|
| `ГГ` | две последние цифры года выдачи | 2000–2099 |
| `ФФ` | код факультета | `09` ИТ, `38` ЭК, `40` ЮР, `31` МЕД |
| `НННН` | порядковый номер в году | 0001–9999 |
| `К` | контрольная цифра | 0–9 |

Пример: `make_number(2024, "ИТ", 42)` → `24-09-0042-7`.

Контрольная цифра считается по цифрам тела номера: веса 2 и 1 чередуются, сумма берётся по модулю 10. Подмена любой цифры делает номер невалидным — это проверяет `is_valid_number`.

Функции модуля `ticket.py`:

- `make_number(year, faculty, seq)` — сгенерировать номер с контрольной цифрой;
- `parse_number(number)` — разобрать номер на части, `ValueError` при неверном формате;
- `is_valid_number(number)` — проверить формат и контрольную цифру (не бросает исключений);
- `next_number(number)` — следующий номер в году, `ValueError` после 9999.

## Как устроен CI/CD

Файл пайплайна: `.github/workflows/ci.yml`.

### Триггеры

- `push` в любую ветку — обязательно прогоняются тесты;
- `pull_request` — тесты до слияния;
- `workflow_dispatch` — ручной запуск.

### Job `test`

1. `actions/checkout` — код репозитория;
2. `actions/setup-python` — Python 3.12;
3. `pip install -r requirements.txt`;
4. `pytest -q` — падение любого теста красит пайплайн.

### Job `deploy` (mock)

Запускается **только** при `push` в `main` и только после успешного `test`:

```yaml
if: github.ref == 'refs/heads/main' && github.event_name == 'push'
```

Шаги: создаётся каталог `deployed/`, в него пишется `VERSION` (SHA коммита) и `EXAMPLE` (пример номера, сгенерированного модулем), затем каталог публикуется как артефакт `deployed-version` через `actions/upload-artifact`.

Это имитация выкладки: реального сервера нет, но результат деплоя виден и скачивается из запуска Actions. Секретов не требуется.

### Что считается успешным деплоем

- job `test` зелёный;
- job `deploy` завершён, артефакт `deployed-version` доступен на странице запуска;
- внутри артефакта есть `VERSION` (SHA коммита) и `EXAMPLE` (валидный номер).

### Где смотреть статус

- вкладка **Actions** репозитория — список запусков и логи;
- badge в шапке этого README;
- для pull request — блок checks под описанием.

## Проверки, которые выполняет CI

| Область | Примеры проверок |
|---------|------------------|
| Генерация | известное значение `24-09-0042-7`, первый и последний номер года |
| Валидация года | 1999, 2100 → `ValueError` |
| Валидация факультета | неизвестный код → `ValueError` |
| Валидация последовательности | 0, 10000 → `ValueError` |
| Разбор номера | round-trip, неверная длина, буквы, неизвестный факультет, номер 0000 |
| Контрольная цифра | сгенерированный номер валиден; номер с изменённой последней цифрой — нет |
| Следующий номер | инкремент последовательности; исчерпание 9999 → `ValueError` |
