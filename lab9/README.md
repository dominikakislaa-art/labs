## Постановка задачи

### 14. Статусы заказа доставки

Переходы created → cooking → delivering → done (+ cancel). Тесты: запрет «назад» без правила. AI-review: таблица переходов vs if-цепочки.

Уточнения, принятые для реализации:

- `created → cooking → delivering → done` — основной путь;
- `cancel` доступен только до передачи курьеру: из `created` и `cooking`;
- из `delivering` отмена запрещена, разрешён только переход в `done`;
- `done` и `cancelled` — терминальные статусы, переходов из них нет;
- любой переход «назад» (например, `delivering → cooking`) запрещён, так как правило возврата в постановке не задано;
- каждый успешный переход фиксируется в истории заказа с меткой времени.

## Реализация

Модель — конечный автомат с одной таблицей допустимых переходов.

| Текущий статус | Допустимые следующие статусы |
|---|---|
| `created` | `cooking`, `cancelled` |
| `cooking` | `delivering`, `cancelled` |
| `delivering` | `done` |
| `done` | — (терминальный) |
| `cancelled` | — (терминальный) |

`ALLOWED_TRANSITIONS` — единственный источник правды. Список следующих статусов и признак терминальности выводятся из него, а не дублируются отдельными условиями.

### Файлы

| Путь | Назначение |
|---|---|
| `order_status.py` | таблица переходов, исключение `OrderStatusError`, класс `Order`, функции `next_statuses` и `is_final` |
| `test_order_status.py` | 18 тестов (с параметризацией — 20+ проверяемых случаев) |

### API

```python
from datetime import datetime, timezone
from order_status import Order, OrderStatusError, next_statuses, is_final

order = Order("A-1001")
order.transition("cooking")
order.cancel()            # допустимо: заказ ещё на кухне
order.status              # "cancelled"

order = Order("A-1002")
order.transition("cooking")
order.transition("delivering")
try:
    order.cancel()        # OrderStatusError: курьеру заказ уже передан
except OrderStatusError:
    pass
order.transition("done")
order.history             # [{"status": "created", "timestamp": ...}, ...]
next_statuses("cooking")  # ["delivering", "cancelled"]
is_final("done")          # True
```

Время можно передавать явно (`Order(..., now=...)`, `transition(..., now=...)`, `cancel(now=...)`); по умолчанию используется текущее время UTC. Это позволяет проверять историю без `sleep` и без подмены системных часов.

- Добавлен параметр `now` с UTC-значением по умолчанию; тесты сравнивают точные метки.
- Неизвестный статус теперь всегда даёт `OrderStatusError`, а не «тихий» `False`.
- `assert` заменён на явные исключения; убраны mutable defaults.
- Сообщения об ошибке содержат id заказа, текущий статус и список допустимых.
- Добавлены тесты на неизвестный статус, терминальные состояния, неизменность истории при ошибке и изоляцию заказов.
- Тесты переписаны без `sleep`: время передаётся аргументом.

### Таблица переходов против if-цепочек

Таблица хранит правила один раз: добавление статуса — одна строка, полнота правил видна целиком, `is_final` и `next_statuses` не дублируют условия, а вычисляются из неё. Цепочки `if/elif` оправданы только при уникальной побочной логике перехода (уведомление, списание денег), но и её лучше выносить в отдельный обработчик. Для пяти статусов принята таблица.

### Этические и практические риски

- **Утечка данных.** В промпт нельзя отправлять реальные заказы, телефоны, адреса и токены доступа. В этой работе использовались только синтетические идентификаторы (`A-1001`).
- **Лицензии.** Сгенерированный фрагмент может оказаться близок к чужому коду; перед публикацией нужна проверка происхождения и условий лицензии. Для учебного проекта код переписан и покрыт собственными тестами.
- **Галлюцинации API.** Модель может уверенно предлагать несуществующие параметры pytest или методы `datetime`. Каждый вызов сверялся с документацией и запускался локально.
- **«Уверенный» неверный код.** Ответы ИИ выглядели завершёнными, но нарушали бизнес-правило (отмена после `delivering`). Защита — тесты на запрещённые переходы и ручное чтение диффа, а не доверие к формулировкам модели.
- **Приватность и воспроизводимость.** Промпты сокращены до учебной постановки; результаты проверены прогоном `python -m pytest -q`, а не «на глаз».
