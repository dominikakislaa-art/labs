## Реализация

`main.py`:

```python
import re
from collections import Counter

SEPARATORS = re.compile(r"[\s,.!?;:]+")


def tokenize(text: str) -> list[str]:
    return [word for word in SEPARATORS.split(text.lower()) if word]


def word_count(text: str) -> int:
    return len(tokenize(text))


def top_word(text: str) -> str | None:
    words = tokenize(text)
    if not words:
        return None
    counts = Counter(words)
    return min(counts, key=lambda word: (-counts[word], word))
```

Ключевые решения:

- одно регулярное выражение на все разделители из постановки (пробелы, `, . ! ? ; :`), поэтому повторные разделители не дают пустых слов;
- `top_word` использует `min` по ключу `(-частота, слово)`: максимальная частота и при равенстве — лексикографически меньшее слово, как требует задание;
- пустой текст и текст только из разделителей дают `[]` и `None` без особых ветвей.

## Red → Green → Refactor

### 1. Red: первая версия не прошла сценарий со знаками препинания

Сначала `tokenize` была написана «в лоб» через `split()`:

```python
def tokenize(text: str) -> list[str]:
    return text.lower().split()
```

Сценарий BDD «Знаки препинания не считаются словами» упал:

```
E   AssertionError: assert ['привет,', 'мир!', 'привет;', 'мир:', 'тест.'] == \
                       ['привет', 'мир', 'привет', 'мир', 'тест']
```

Одновременно упал юнит-тест `test_tokenize_lowercases_and_strips_punctuation`.
Это ожидаемое «красное» состояние: тест описывает требование, которого ещё нет.

### 2. Green: минимальное исправление

Заменила `split()` на разбиение по регулярному выражению:

```python
SEPARATORS = re.compile(r"[\s,.!?;:]+")
return [word for word in SEPARATORS.split(text.lower()) if word]
```

Оба теста позеленели, ничего другого менять не пришлось.

### 3. Red → Green для `top_word`

Сначала `top_word` возвращал `max(counts, key=counts.get)`. Сценарий «При ничьей выбирается лексикографически меньшее слово» упал:

```
E   AssertionError: assert 'яблоко' == 'банан'
```

Причина: `max` при равной частоте возвращает первое встреченное слово, а не меньшее.
Исправление — ключ `(-counts[word], word)` и `min`, после чего сценарий и юнит-тест
`test_top_word_tie_returns_smallest` стали зелёными.

### 4. Refactor

- вынесла регулярное выражение в константу `SEPARATORS`, чтобы не компилировать его на каждый вызов;
- `word_count` и `top_word` теперь используют `tokenize`, а не дублируют разбиение;
- заменила ручной подсчёт словарём на `collections.Counter` — короче и без ошибок с инициализацией;
- добавила параметризованный тест на строки только из разделителей.

После рефакторинга все 14 проверок остались зелёными — поведение не изменилось.
