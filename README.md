## Постановка задачи

### 14. Карта этажей учебного корпуса (текстовая схема)

ASCII/Markdown-схема помещений. Ветка `renumber-rooms` меняет нумерацию; ветка `add-labs` добавляет лаборатории, затрагивая те же фрагменты схемы. Разрешите конфликт схемы.

### Общие правила

- Язык мини-проекта на выбор; достаточно небольшого объёма, чтобы конфликт был наглядным.
- Конфликт должен быть реальным: две ветки меняют одни и те же строки по-разному.
- В истории коммитов видно: начальная работа → работа в ветках → конфликт → разрешение → синхронизация с remote.
- Сообщения коммитов осмысленные, единый стиль.
- Не удалять историю после разрешения конфликта «переписыванием ради красоты».
- Репозиторий публичный (или доступный по ссылке без запроса доступа).

## Ход работы

### 1. Инициализация репозитория

```bash
git init -b main
git add README.md floor-map.md
git commit -m "init: карта этажей корпуса Б"
```

Исходная схема: 1 и 2 этажи, номера `101–105` и `201–205`, аудитории и кафедра ИТ.

### 2. Ветка `renumber-rooms`: смена нумерации

```bash
git checkout -b renumber-rooms
# правки floor-map.md: 101 → 1-01, 102 → 1-02, …, 205 → 2-05
git add floor-map.md
git commit -m "refactor: перейти на нумерацию «этаж-номер»"
```

В этой ветке изменены все строки таблиц обоих этажей (столбец «№» и названия аудиторий), вводная строка про нумерацию и ASCII-схемы.

### 3. Параллельная работа в `main`

Пока ветка `renumber-rooms` не слита, в `main` добавлен раздел с правилами обновления схемы:

```bash
git checkout main
git add floor-map.md
git commit -m "docs: добавить правила обновления схемы"
```

### 4. Первое слияние (без конфликта)

```bash
git merge renumber-rooms -m "merge: нумерация «этаж-номер» в main"
```

Изменения в `main` (раздел в конце файла) и в `renumber-rooms` (таблицы) не пересекаются, поэтому Git слил их автоматически.

### 5. Ветка `add-labs`: новые лаборатории

Ветка создана от `main` **до** слияния нумерации, поэтому в ней ещё старые номера:

```bash
git checkout -b add-labs
# 204 «Аудитория 204» → «Лаборатория информатики»
# добавлены строки 206 «Лаборатория робототехники» и 207 «Лаборатория сетей»
# ASCII-схема 2 этажа продлена до [206]—[207]
git add floor-map.md
git commit -m "feat: добавить лаборатории 206 и 207 на 2 этаже"
```

### 6. Конфликт

```bash
git checkout main
git merge add-labs -m "merge: лаборатории 206-207"
```

```
Auto-merging floor-map.md
CONFLICT (content): Merge conflict in floor-map.md
Automatic merge failed; fix conflicts and then commit the result.
```

Обе ветки правили один и тот же блок таблицы 2 этажа: `renumber-rooms` переименовала строки 204–205, а `add-labs` изменила строку 204 и добавила 206–207. Фрагмент файла с маркерами:

```markdown
## 2 этаж

<<<<<<< HEAD
| 2-04 | Аудитория 2-04 | 28         |
| 2-05 | Аудитория 2-05 | 20         |
=======
| 204 | Лаборатория информатики | 28    |
| 205 | Аудитория 205   | 20          |
| 206 | Лаборатория робототехники | 16 |
| 207 | Лаборатория сетей | 18        |
>>>>>>> add-labs
```

### 7. Разрешение конфликта

Конфликт разрешён вручную: взята **новая нумерация** из `renumber-rooms` и **новые помещения** из `add-labs`. Ни одна сторона не отброшена, маркеры удалены:

```markdown
## 2 этаж

| №    | Помещение                 | Вместимость |
|------|---------------------------|-------------|
| 2-01 | Аудитория 2-01            | 40          |
| 2-02 | Аудитория 2-02            | 32          |
| 2-03 | Кафедра ИТ                | —           |
| 2-04 | Лаборатория информатики   | 28          |
| 2-05 | Аудитория 2-05            | 20          |
| 2-06 | Лаборатория робототехники | 16          |
| 2-07 | Лаборатория сетей         | 18          |

2 этаж:  [2-01]—[2-02]—[2-03]—коридор—[2-04]—[2-05]—[2-06]—[2-07]
```

Проверка после разрешения:

```bash
grep -n "<<<<<<<\|=======\|>>>>>>>" floor-map.md   # пусто — маркеров нет
git add floor-map.md
git commit -m "merge: согласовать нумерацию «этаж-номер» и лаборатории 206-207"
```

История сохранена обычным merge-коммитом (без rebase и без «переписывания»), поэтому в `git log --graph` видно оба слияния и сам факт конфликта.

### 8. Удалённый репозиторий: push и pull

В учебной версии remote — локальный bare-репозиторий (имитация GitHub, чтобы сценарий можно было воспроизвести без доступа к сети). Он вынесен за пределы папки работ — в `D:\Desktop\lab5-origin.git`, чтобы не засорять сдачу:

```bash
git init --bare ../../lab5-origin.git
git remote add origin ../../lab5-origin.git
git push -u origin main
git push origin renumber-rooms add-labs
```

Сценарий «второй разработчик»: клон, правка, push, затем pull в основной копии:

```bash
git clone ../../lab5-origin.git ../../lab5-clone
cd ../../lab5-clone
# добавлен раздел «Доступная среда»
git commit -am "docs: добавить раздел о доступной среде"
git push

cd -   # вернуться в lab5
git pull origin main
# Updating c797880..458ab37
# Fast-forward
```

История этой работы опубликована в общем репозитории лаб отдельными ветками:

```bash
git push github main:refs/heads/lab5/main
git push github renumber-rooms:refs/heads/lab5/renumber-rooms
git push github add-labs:refs/heads/lab5/add-labs
```

`lab5/main` — итоговое состояние с merge-коммитом, `lab5/renumber-rooms` и `lab5/add-labs` — ветки до слияния (по ним видно, откуда взялся конфликт).
